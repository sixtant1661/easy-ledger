# 简单记账助手（Easy Ledger）产品需求

## 1. 文档状态与目标

本文件是需求分析草案。用户明确提出的要求是产品约束；标记为“待确认”的结算规则必须确认后才能作为正式默认行为实现。推荐方案仅供决策，不代表用户已接受。

目标用户首先是习惯在手机办公软件中填写 Excel 结算单的中老年人。产品服务于人工、运输、机械等按工作量结算的业务，不是消费记账软件。核心原则：记录简单、计算准确、核对方便、导出专业、数据安全。

第一版本地离线运行，不依赖账号、云服务器、广告或分析 SDK，不申请非必要网络权限。数据放在应用私有存储，不将真实业务数据提交到 Git。

## 2. 用户流程

- 日常记录：选择项目 → 今天（可选昨天、前天或日历日期）→ 填写业务及时间段或直接填数量 → 核对数量、单价和金额 → 保存。
- 项目核对：项目详情 → 按日期查看记录 → 编辑、复制或删除 → 汇总金额随记录变化重新计算。
- 后续补录：选择日期范围 → 生成连续日期 → 跳过休息日、复制上一天或补记遗漏日期 → 逐日核对 → 保存到同一数据库。
- 后续结算：选择项目和记录范围 → 核对统一结算内容 → 建立快照 → 预览、导出、分享。

## 3. 第一阶段功能范围

### 项目

支持创建、修改和归档多个项目；保存项目名称、默认业务名称、计费方式、单位及单价。归档保留历史数据，不等于删除。统一结算结构支持显示列名配置；列名不决定计算逻辑或数据库字段。

### 单条记录

支持新增、编辑、删除和复制，按日期排列。日期默认手机当天，通过快捷按钮和日历选择器修改，不要求手输日期字符串。复制生成独立记录，保存前核对新日期。建议复制时重新选择目标日期，避免无意重复，具体重复策略见待确认表。

记录保存业务名称、计费数量、单位、单价、备注和零个或多个工作时间段。支持小时、天、次、件、自定义单位。允许无时间段直接填数量。实际工时与计费工时分别保存，支持手动调整最终计费数量；非小时计费的数量也可手动填写。

时间使用选择器，动态添加、删除、修改时间段，支持跨午夜。重叠检查包含跨午夜后的真实区间，首尾相接允许。异常说明指出具体时间段，不能只显示“输入错误”。时间段非法或重叠时不得保存为有效记录；可选草稿功能不在第一阶段。

### 计算及核对

金额 = 计费数量 × 单价，使用精确十进制；禁止使用 Float/Double 计算业务金额。项目总额从有效记录重新汇总，编辑和删除后更新。记录显示实际时长、最终计费数量、单价和金额；手动调整应有清晰标识。

禁止静默修改历史记录：修改项目默认单价、业务名称或单位，仅为新记录提供默认值；推荐方案待用户确认。调整已保存记录必须走明确编辑流程。

### 适老化

Corporate Clean：主色 #2563EB，背景 #F8FAFC，卡片 #FFFFFF，主文字 #111827，次文字 #4B5563，边框 #E5E7EB。适度圆角和轻微阴影，无渐变、霓虹和复杂动画。

常规正文至少 18sp，主要按钮至少 56dp，其他触控目标至少 48dp。支持系统字体缩放，避免固定文本区域高度；金额和单位不能因放大字体而不可见。操作提供按压反馈，错误不只依赖颜色表达。破坏性操作需要确认，保存失败保留输入，保存中防止重复提交。

## 4. 后续范围

批量补录与单条录入共用领域规则和 Room 数据库，不另建表格数据库。跨日复制必须重新验证日期及时间段。

统一结算结构包括标题、项目名称、日期、业务名称、工作时间、时长或数量、单位、单价、金额、备注、合计、负责人签字区域。项目可以修改显示列名，不引入行业专属表格结构。

.xlsx 导出：每个时间段一行、以换行连接；按内容和段数设置行高、自动换行、居中、列宽、边框及打印布局，禁止靠大量空格排版。拿到原始 Excel 后再定义模板验收基准；当前不声称能够复刻未知模板。

APP 表格预览、Excel、PDF、PNG 消费同一份不可变结算文档和快照，业务内容、金额、顺序、列名一致；分页和像素排版可因媒介不同而变化。使用 Android 系统分享，微信是否能够接收由设备和接收应用决定，必须实机验证。

历史结算单保存创建时的数据、列名、格式版本和合计，不能跟随项目及记录修改而变化。备份恢复需包含结构版本和完整性校验，导出到用户选择的位置；不要求广泛存储权限。

## 5. 待确认业务规则

下表推荐方案均未获得确认。初始化可先搭建模型与测试边界，但结算实现前必须形成决策记录。

| 问题 | 推荐默认方案 | 影响 |
| --- | --- | --- |
| 币种与金额舍入 | 首版人民币，金额保留 2 位小数，HALF_UP；每条金额先舍入，再汇总显示金额 | 单条和合计可能与“先汇总后舍入”差 0.01 元 |
| 分钟如何换算小时、数量精度 | 输入精度为分钟，实际时长保存整数分钟；计费小时最多保留 2 位小数，自动换算建议 HALF_UP（自动换算方式仍待确认）；不自动按半小时或整小时进位 | 1 分钟等分数小时需要明确精度和计算顺序 |
| 手动数量与自动数量 | 小时计费默认实际分钟换算；调整后保持手动模式，修改时间段时提醒并保留手动值，提供“恢复自动” | 防止覆盖人工结算约定 |
| 按天计费的换算 | 不从工时自动推导天数，默认手填；可支持半天等小数 | “一天几小时”不应被隐式假定 |
| 跨午夜和跨度 | 时间段明确标记结束日为当天/次日，首版最长不超过 24 小时；开始等于结束时提示选择零时长或全天，不自行推断 | 防止将输入错误解释为整天工作 |
| 跨日记录归属与日期范围 | 按记录工作日期归属，跨午夜段完整计入开始日期，不拆到第二天，保存完整起止日期时间 | 影响项目日报及结算日期范围 |
| 重叠检查范围 | 同一记录内阻止重叠；同项目不同记录重叠明确警告，由用户核对；不同项目不阻止 | 并行人员或设备业务可能合法重叠 |
| 同日多条与复制重复 | 允许同项目同日多条，不设日期唯一约束；疑似重复提示确认 | 同日可能存在多个业务或单价 |
| 数量、单价为零或负数 | 允许非负值；零值提示，负数不支持；冲销单另行设计 | 免费、休息日及退款需区分 |
| 单价和单位历史行为 | 记录保存业务名称、单位、计费方式、单价快照；项目默认值修改不追溯历史 | 保证已录入结算依据稳定 |
| 列名修改和结算快照 | 项目当前列名用于新预览，历史结算快照保留旧列名 | 表格可改，既有结算单不变 |
| 删除及归档 | 记录软删除，提供撤销；项目只归档不物理删除；保留期及清理策略待确认 | 影响存储、恢复和防误删 |
| 备份与恢复 | 系统文件选择器手动备份，恢复前备份当前数据；首版优先整库替换而非合并 | 合并可能重复数据，需另定规则 |
| 结算范围及已结算标记 | 按日期及记录选择创建快照，不默认冻结源记录；显示历史快照关联 | 是否允许重复结算或编辑已结算记录需确认 |

## 6. 第一阶段验收

1. 能通过受支持工具链构建 Debug APK，在约定 Android 真机或模拟器安装并启动；最低系统版本及测试设备在初始化时记录。
2. 创建至少两个项目，修改默认值，归档后历史数据仍可查询，重启应用数据仍存在。
3. 可以新增、编辑、复制、删除记录；支持日历和今天/昨天/前天，取消编辑不修改数据库。
4. 一条记录支持零个、一个、三个及更多时间段；07:00–11:00、13:00–17:00、18:00–20:00 自动合计 600 分钟。
5. 跨午夜计算、重叠拒绝、首尾相接允许及日期归属均遵守已确认规则；无时间段的手工数量可以保存。
6. 实际分钟与计费数量独立持久化，手动模式可识别；修改数量、单价和记录后项目总额正确更新。
7. 金额和舍入边界通过单元测试；如 0.1 × 0.2 的精确结果为 0.02，不出现二进制浮点尾差。
8. 列名使用稳定键持久化，可通过基础设置编辑并在记录核对区域显示；不改变计费含义。
9. 正文、按钮、字体缩放、横竖屏或状态恢复、清晰错误及删除确认完成 UI 验证；目标 200% 字体下核心流程可操作。
10. Room 多表保存原子性、删除后汇总、进程重建数据恢复完成有意义的数据库/设备测试。
11. 交付源码、测试结果、构建命令、Debug APK 路径与已知限制；未执行的检查标记为未执行。
12. 无广告、分析 SDK、账号或非必要权限；真实数据、签名密钥和本地 SDK 路径不进入版本控制。

第一阶段不以完整备份恢复、批量补录或导出能力作为通过条件，必须明确提示这些能力尚未提供；基础版不应在无备份情况下用于唯一副本的正式生产记账。

## 本轮暂定业务政策（待产品方最终确认）

以下由产品方授权作为暂定默认方案。状态统一为「待产品方最终确认」，不是最终结算合同；本里程碑仅记录政策，不实现结算功能。

1. 单条金额以精确十进制计算，按 HALF_UP 保留两位小数；合计为各行已舍入金额之和。
2. 实际工时按整数分钟计算；计费小时可手动调整，最多两位小数。分钟自动转换为小时的取整方式仍待最终确认，推荐 HALF_UP；例如 1 分钟可显示为 0.02 小时，但实际工时仍保存 1 分钟。
3. 按天计费默认手动填写天数，不从实际工时自动换算。
4. 修改计费数量保留原始工作时间段和实际工时，重新计算金额；修改时间段后如何处理已有手动数量仍按待确认政策提示。
5. 跨午夜工作归属开始日期，保存完整起止日期时间。每段均存起止 LocalDateTime；首版建议同一记录各段从工作日期开始，后续日期段输入及超 24 小时限制仍需确认。墙钟工时与夏令时真实经过时长的选择仍待确认。
6. 同一天允许多条记录；疑似重复提醒，不强制禁止。同条记录内的时间段重叠仍阻止，首尾相接允许。
7. 每条记录独立保存当时单价，项目默认单价修改不追溯历史记录。
8. 结算单工作时间上下排列，每段一行，按时间段数量、换行文本及字体自动计算行高，不用空格排版。

### 三星设备验证约束

妈妈使用三星 Android 手机，型号、Android 和 One UI 版本待确认。不能将暂定 minSdk 当成已获认可的最低支持版本。本次只提供首页、项目占位与设置；后续日期/时间选择、最大字体及屏幕缩放、手势/三键导航、文件选择器、Excel 打开与微信分享都需在目标三星设备测试。不得因使用系统或 Material 组件就声称 One UI 兼容通过。

## 0.2 本地工作记账里程碑

目标设备已确认 Galaxy S21 FE / Android 16 / One UI 8.0，基础版已有用户实机验收。本轮保留原风格和导航，增加 Room 本地项目/记录、手动数量计费、日历和快捷日期、历史详情、关键词搜索与首次三步引导。工时段输入、批量补录、导出及备份恢复未实现。

用户已确认数量大于 0、单价允许 0、拒绝负数冲销、小时数量最多两位小数；按天手填。金额继续精确十进制 HALF_UP 两位并合计舍入后各行金额。记录单价独立快照，不受项目默认单价修改影响。

实际 Room v2 模型见 data/local：Project、WorkRecord、WorkSegment（未来扩展）、Preference。项目备注用于搜索，v1→v2 显式迁移增加备注列；v1 为测试基线，未向用户发布。项目/记录软删除，项目删除保留记录；数量改变不删除原时间段。项目列名和结算快照目前仍是后续设计，未声明实现。

首次引导完成/跳过持久化于 Room，设置入口可重看。搜索使用本地 SQL 字符串包含查询，百分号/下划线按字面关键词处理，不作为通配符。金额不使用 SQLite REAL 或 SUM(text)。多表写入事务化，不启用破坏性迁移。

验收必须包含新增/编辑/删除、价格快照、金额/舍入、搜索、事务回滚、数据库文件重开、v1→v2 迁移、引导和 UI、同签名覆盖安装的数据保留。测试结果按实际执行记录至 BUILD_STATUS。API 35 模拟器不能代替三星 Android 16 真机验收。

下一优先项是可导出、校验、可回退的本地备份恢复，使用 SAF，不访问服务器。不将手机数据库、签名私钥或真实记录提交 Git。签名缓存失效拒绝更新包，固定发布密钥必须另行安全配置；卸载/清除数据会丢失记录。
